# MITI 4.2.1 behavior coding reference (curated summary)

Source: Moyers, Manuel & Ernst (2015), MITI 4.2.1 Coding Manual. Each entry cites the manual
section it summarizes. This is a paraphrased summary for an automated coder, not manual text.
Examples are short illustrations written for this reference.

## 1. Units and volleys (E.1, E.1.a, E.3)

- A **volley** is an uninterrupted stretch of counselor speech; it ends when the client speaks.
  (E.1)
- A **facilitative** client response ("mm-hm", "yeah", "right", "ok") that only acknowledges the
  counselor does NOT end the volley; the counselor's next turn continues the same volley. It DOES
  end the volley when it answers a direct question or confirms/rejects a reflection. When unsure,
  prefer fewer parses, i.e. treat it as the same volley. (E.3)
- A volley is split into **utterances** (units): one complete thought each. (E.1.a)
- Each unit gets at most ONE code; some units get none. (E.1.a, F)
- When unsure whether to split, split less. (E.1.a decision rule)
- Split on meaning, not punctuation: a reflection followed by a question is two units; several
  questions asked in a row can be one unit. (E.1.a, E.2)

## 2. Behavior codes

### Giving Information — GI (E.4.a)
Gives information, educates, gives feedback, or states a professional opinion in a neutral tone,
without trying to persuade, advise or warn, and without implying the client must act on it.
- Not GI: **structuring statements** about what will happen in the session, instructions for an
  in-session exercise, scheduling the next appointment. These are not coded. (E.4.a.1)
- Example (GI): "Most people need a few weeks to get used to a new medication schedule."

### Persuade — P (E.4.b; MINA, E.4.g.1)
An overt attempt to change the client's opinions, attitudes or behavior using logic, arguments,
self-disclosure or facts linked to a message to change; OR giving advice, suggestions, tips,
opinions or solutions (including biased information) **without** permission or a clear autonomy
cue.
- Decision rule: if unsure between P and GI, code GI. The bar for P is high. (E.4.b)
- Example (P): "You should check your blood sugar every morning, it's the only way to stay safe."
- Example (GI, not P): "Morning readings tend to be the most stable."

### Persuade with Permission — PWP (E.4.c)
Persuasion given under a condition of permission:
1. the client directly asked for the counselor's opinion or advice, or
2. the counselor asked permission to advise/share/discuss, or
3. the advice is prefaced or qualified with autonomy-supportive language so the client may
   discount or evaluate it.
- Permission may come before, during or shortly after the advice; a general permission can last
  for several minutes, but lapses if the counselor changes topic, becomes directive or starts
  adding substantial content or a plan without asking again. (E.4.c)
- If neutral, code GI instead; if unsure between PWP and GI, code GI. (E.4.c)
- If the unit also contains an explicit Seek or Emphasize thought, code those too (separate
  units). (E.4.c)
- If one unit meets both P and PWP, code PWP. (E.4.c.1)
- Overly frequent, perfunctory or overstretched permission is still PWP; it affects the
  Partnership global, not the code. (Appendix B FAQ 5)
- Example (PWP, after the client said "sure" to sharing ideas): "Some people find it helps to keep
  the floss next to the toothbrush."

### Question — Q (E.4.d)
Any question (open, closed, evocative, fact-finding). Open and closed are not distinguished.
- Only one Q per volley is counted. (E.4.d)
- Asking what the client already knows about a topic is Q, not Seek. (E.4.f.3)
- A setup statement that only cues the topic of the question ("You mentioned X. How ...?") is
  part of the question and not a separate reflection, unless there is a clear stop that lets the
  client respond. (E.4.e.5)
- Do not code by the question mark alone: a question can be Seek, Emphasize or Confront by
  function. (E.4.f.3, E.4.g.2)

### Reflections — SR and CR (E.4.e)
A statement that captures and returns something the client said; it may add meaning but stays
anchored in the client's words. A statement phrased as a question is Q, not a reflection.
- **Simple Reflection (SR)** adds little or no meaning or emphasis; may name a strong emotion the
  client expressed; a summary that adds no new point or direction is SR. (E.4.e.1)
- **Complex Reflection (CR)** adds substantial meaning or emphasis: a deeper or more complex
  picture, emphasizing part of what was said to make a point or shift direction, metaphor,
  double-sided reflection, or a directional summary. (E.4.e.2)
- If unsure between SR and CR (including summaries), code SR. (E.4.e.2 decision rule)
- A volley gets only one reflection code: CR if any reflection in it is complex, otherwise SR.
  (E.1.a, E.4.e.3)
- A reflection followed by a checking question gets both codes. (E.4.e.4)
- Example: client "I keep forgetting the evening pills." SR: "The evening dose slips your mind."
  CR: "Evenings are when your routine falls apart."

### Affirm — AF (E.4.f.2; MIA)
Accentuates something genuinely positive about the client: a specific strength, effort,
intention or worth, explicitly tied to the client's behavior or characteristics.
- Not AF: agreement, approval, cheerleading, generic praise ("Great!", "I'm proud of you"), or
  general support/sympathy ("It's always hard at the start"). These are not coded. (E.4.f.2)
- If a unit is both an affirmation and a (complex) reflection, AF wins. (E.4.f.2)
- If not sure it is specific or strong enough, do not code AF. (E.4.f.2)
- Repeating the same affirmation many times: only the first two or three are coded; mark a
  repeat by pointing to the earlier turn with the same affirmation. (E.4.f.2.a)
- Example (AF): "You set up the pill box yourself, even on a busy week."

### Seeking Collaboration — SEEK (E.4.f.3; MIA)
Explicitly shares power or acknowledges the client's expertise: genuinely seeks consensus on
tasks, goals or direction of the session; asks permission to give information or advice; asks
what the client thinks of information provided when it is a genuine effort to share power.
- Not Seek: asking about the client's knowledge (Q); rote or rhetorical "what do you think?" that
  only tests understanding. If you cannot decide, do not code Seek. (E.4.f.3, Appendix B FAQ 9)
- Example (SEEK): "Would it be ok if we looked at your meal plan together today?"

### Emphasizing Autonomy — EA (E.4.f.4; MIA)
Clearly places responsibility and choice with the client: their control, freedom of choice,
personal autonomy, or ability/obligation to decide about their attitudes and actions.
- Not EA: statements about self-efficacy or confidence to perform an action ("You can do it").
  (E.4.f.4)
- Example (EA): "How often you check is really your call."

### Confront — CONFRONT (E.4.g.2; MINA)
Directly and unambiguously disagrees, argues, corrects, shames, blames, criticizes, labels,
warns, moralizes, ridicules or questions the client's honesty, with uneven power and
disapproval. A question or reflection with a clearly confronting tone is Confront.
- Restating negative information the client disclosed can be Confront or a reflection; decide by
  tone and context. If not sure between Confront and a reflection, do not code it. (E.4.g.2)
- Confront takes precedence over Q. (E.4.g.2)
- Using a confrontational form to stress a client strength may be Affirm instead. (E.4.g.2)
- Example (CONFRONT): "You told me you were taking them, but the bottle is still full?"

## 3. When a unit fits more than one code (E.4.f.1, E.4.f.1.a, E.4.g.3)

Report the main code in `code` and the second candidate in `alternative_code`. Set `certain`
to true only when you are confident in the code(s); otherwise false. The final code is resolved
by deterministic rules after your answer, so report what you see honestly instead of resolving
it yourself:
- MIA pyramid (top to bottom): Emphasize > Seek > Affirm. Higher codes need reasonable
  confidence; when unsure, the lower code applies. (E.4.f.1)
- MIA vs another code (e.g. Q or a reflection): when unsure, the other code applies. (E.4.f.1.a)
- MINA hierarchy: Confront > Persuade. (E.4.g.3)
- Only assign an MIA code when the unit clearly "rings the bell". (E.4.f)

## 4. Not coded (F)

Greetings, structuring statements, purely facilitative remarks ("ok", "mm-hm"), references to a
previous session's content, incomplete thoughts, off-topic remarks, apologies or self-disclosure
without another function, and general support statements. Return such units with `code: null`.
